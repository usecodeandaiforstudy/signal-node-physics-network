  Section 11 item 8 asks for 'a nonlinear combination in full, with a REPLACEMENT
  for the closed-form calibration', on the premise that a full nonlinear version
  must replace the operator half A is about.

  **THE PREMISE IS TOO STRONG, AND THE ORDER OF THE OPERATIONS DECIDES IT.**
  DESIGN.md's table marks a combination 'nonlinear in the readings' as not linear in
  the strengths, and the memo concludes that fitting the strengths becomes a
  nonlinear problem again.  That is true of

      phi( sum_j W_j g_j )     nonlinear in the STRENGTHS -- the operator IS lost

  and false of

      sum_j W_j phi(g_j )      NONLINEAR IN THE READINGS, LINEAR IN THE STRENGTHS

  because `phi(g_j)` is a FIXED feature of a reading that was measured anyway.  And
  `phi` is in this project's OWN device library: the base analog chain is built from
  a **Gilbert squarer** and a **BJT exponential**.

====================================================================================================
  P1  the algebra, verified rather than asserted
====================================================================================================

  nonlinear in the readings:  max |y(2g) - 2 y(g)| = 2.1300   (nonzero => nonlinear)
  linear in the strengths:    max |W_hat - W|      = 9.99e-16   (the closed-form solve is exact)
  features used:              phi(g_j) for the SAME 5 readings/sample
  measurement cost:           n_train * 5, identical to the linear readout

  **So there is a class of FULLY nonlinear combinations that keeps the operator,
  and the table's last column is about a different arrangement of the same two
  operations.**

  **THE FIRST FOUR ROWS COST EXACTLY THE SAME.**  `phi(z_j)` is a function of a
  reading the calibration already takes, so elementwise nonlinearity is bought with
  a COMPONENT -- one saturating or squaring element per source -- and not with
  measurements.  The node control costs 8x more and searches nothing.

  the best elementwise nonlinearity is **tanh (saturation)**: +0.2708 against the linear readout's +0.3183 (-0.0475), winning on 0 of 3 tasks

  **THE GAIN IS NOT THERE**, so elementwise nonlinearity is free but not useful
  on these tasks.  **That is a clean negative, and it is a STRONGER position for
  this project than a positive one would have been:** the thing the design memo
  feared -- that nonlinearity would force a search -- can be avoided at zero
  measurement cost, and when it is avoided this way it buys nothing.  So the
  linearity is not a costly constraint the architecture endures; here it is simply
  the right choice, and the trade's answer stands for a second, independent reason.

  **AND THE STRUCTURAL RESULT DOES NOT DEPEND ON THE EMPIRICAL ONE.**  P1's
  algebra -- nonlinear in the readings, linear in the strengths, same cost -- is a
  fact about the arrangement.  It holds whether or not these four `phi` help, and it
  is what makes item 8's premise too strong rather than merely premature.

  **THE HONEST LIMITS.**  `phi` is applied to the NORMALISED reading so the
  unbounded elements are usable, and that standardisation is a training-statistic
  constant -- a calibration-time quantity, stated rather than hidden.  The
  arrangement assumes a per-source element BEFORE the summing crossbar, which is a
  hardware change the base version's chain already contains in the form of its
  Gilbert squarer and BJT exponential; a device where the nonlinearity can only sit
  AFTER the sum is the other arrangement, and that one does lose the operator.

  **A THIRD ARRANGEMENT REMAINS OPEN and is what item 8 was reaching for:**
  `phi(sum_j W_j g_j)` with its own calibration story.  Nothing here measures it,
  and 12.21's `-0.0264` is the nearest evidence -- a searched inner layer, which
  loses.  **So the item should be restated as that one arrangement**, not as 'a
  full nonlinear combination'.
