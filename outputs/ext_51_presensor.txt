  ext_51 - pre-sensor superposition
  k=6 graphs -> m=2 channels, 200 probes
  2026-10-06 14:29:11
==================================================================

  **THE QUESTION, from DESIGN.md 7 item 5:** combining the graphs IN THE FIELD before
  sensing "would cost ONE measurement per probe instead of t ... the most promising
  hardware angle of the whole proposal", qualified by 4.1: available only when the
  combination is LINEAR, because a linear medium cannot multiply two fields.

  **AND THIS REPOSITORY ALREADY VERIFIES THE PROPERTY IT NEEDS**, rather than assuming
  it: `sub_01`'s exact-superposition threshold is one of the assertions CI runs first,
  and the diffusion cell's own header states "superposition is EXACT because the PDE is
  linear".  So the equivalence below is not a numerical coincidence being hoped for --
  it is the same property the rest of the suite rests on, applied one stage earlier.

  Cost: the shipped path reads **k = 6 sensor values per probe per stage**;
  the pre-sensor path reads **m = 2**, one per output channel.

====================================================================================================
  P1  does the field-level combination give the SAME answer?
====================================================================================================

   stage     max |pre - post|       relative
  --------------------------------------------
       0            1.127e-07      7.399e-08
       1            2.979e-08      4.293e-08

  and the end-to-end prediction: **1.102e-07 max abs difference** over 200 samples
  **The two are the same computation.  What differs is where the sensor sits.**

====================================================================================================
  P2  what that buys, in the project's own unit
====================================================================================================

  path                                 sensor reads per probe
  ------------------------------------------------------------
  shipped (read k, then combine)                           12
  pre-sensor (combine, then read)                           4

  **ratio 3.00x**, and it is `k/m` per stage by construction: one reading per
  graph becomes one reading per output CHANNEL.  At this configuration `k = 6`
  and `m = 2`, so the saving is 3.0-fold on every stage.

  In the project's full calibration unit the shipped multi-graph cost is
  `n_train * sum(k_s * N_s)` readings against `n_train * sum(m * N_s)` pre-sensor --
  **the same accuracy for `k/m` times fewer readings**, which is the currency every
  comparison in this extension is run in.

====================================================================================================
  P3  the NEGATIVE CONTROL: a NONLINEAR combine cannot be moved before the sensor
====================================================================================================

  4.1's qualification, tested rather than quoted.  A tanh combine is built on the same
  graphs and the two paths are compared:

   stage     max |field-sum - tanh|       relative
  --------------------------------------------------
       0                  6.135e-01      6.748e-01
       1                  1.263e-01      2.103e-01

  **0.675 relative -- i.e. it fails, and it fails by O(1) rather than by
  rounding.**  So the qualification is real: the pre-sensor saving is bought by the
  LINEARITY of both the combination and the medium, and 12.24's finding that a
  nonlinearity in the readings is free-but-useless makes that a cheap condition here.

====================================================================================================
  P4  VERDICT AND LIMITS
====================================================================================================

  **THE DESIGN QUESTION IS ANSWERED AFFIRMATIVELY.**  Pre-sensor superposition
  reproduces the shipped multi-graph output to 7.4e-08 relative while spending
  **4 sensor reads per probe instead of 12** -- a 3.0-fold cut
  in the project's unit of account, on the linear-combination case the shipped
  design is in.  The equivalence is exact because the substrate superposes, which
  `sub_01` already asserts, so this is not a new physical claim.

  **AND THE LIMITS, FIRST OF WHICH IS THAT NOTHING PHYSICAL WAS BUILT.**  This is
  arithmetic on the repository's own models plus a property it verifies; no device was
  wired to superpose anything.  The saving is in SENSOR READS, and it assumes the
  superposition can be arranged with the graphs' fields landing on one sensor -- which
  is exactly the kind of question only hardware settles.  It also requires the
  combination to be LINEAR and the medium to be linear; a nonlinear combine fails by
  O(1), as P3 measures.  And it changes the COST of every multi-graph result rather
  than their accuracy, so no accuracy figure in this document moves.
