  A CONFOUND IN P3, reported rather than smoothed over: the corrected score
  does NOT fall monotonically with drift, because a drift makes the realized
  widths LARGER and this node set happens to prefer wider widths -- the same
  one-sided effect ext_11 measured (+0.6216 at +10% width).  The width ERROR
  against the plan does grow monotonically, so the correction does go stale;
  it is the SCORE that cannot register it here.  A drift test that could
  register it would need widths the plan already prefers, which this plan
  does not have.

==========================================================================================
  VERDICT: how far does the closed loop actually generalise?
==========================================================================================

  P1 pooled estimator beats the open loop by 0.02 anywhere: NO
  P1 per-node inverse recovers the error-free score at every spread: YES  (reference +0.5818)
  P2 the width error converges to below 0.02 at every beta: YES  (worst 0.0087 at beta=1)
  P3 the correction beats the open loop for a drift up to 0.40

  THE LOOP GENERALISES, BUT NOT WITH ext_12's ESTIMATOR.  The pooled gain
  fails on per-node error and fails SILENTLY: averaging independent errors
  returns ~1.0, which reads as 'the actuator is fine' while every node is
  wrong.  The per-node inverse uses the same measurement without
  averaging and recovers the model at every spread tested.

  So the corrected procedure -- superseding ext_12's -- is:

      place -> measure each node -> invert PER NODE -> re-command
      -> (iterate if the gain depends on the command)
      -> calibrate the strengths

  ext_12's pooled form is a special case of this, valid only when the
  error really is common; it should be read as such rather than as the
  general repair.
