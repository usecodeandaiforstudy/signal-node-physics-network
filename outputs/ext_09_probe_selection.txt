  The refinement counters are not decoration: the first version of this
  experiment reported IDENTICAL scores for two different selection rules,
  which is what a step that never fires looks like from the outside.

  max |centres(leverage) - centres(all)| per seed: 1.210e-07, 0.000e+00, 0.000e+00
  float32 floor on unit-scale coordinates: 4.8e-07 (4 x eps); anything at or below it is rounding
  -> the refinement does NOT move the model: its accepted changes are
     rounding, and on most seeds there is no change at all.

     The MECHANISM, which is worth stating because it is a property of
     the operator rather than a bug: OP-G inverts a response, so refining
     a node against a residual that this node already explains returns the
     SAME node -- a fixed point.  GROW + SOLVE place each node to fit the
     current residual, i.e. already at that fixed point, so REFINE has
     nothing to move.  It would only bite if a node were misplaced, which
     is a fault-tolerance use rather than a training one.

     CONSEQUENCE FOR ext_07: its +0.5817 comes from
     GROW + SOLVE + GATE.  Claiming a trainer that uses 'all the operators'
     would overstate it; REFINE is implemented and verified but inert here.
