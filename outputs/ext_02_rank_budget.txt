  Closed form, not training: the readout is linear in the strengths, so
  'best achievable readout' is a least-squares problem.  Geometry is taken
  from a real base model and HELD FIXED, so this isolates the readout.

  It is built to be able to answer NO.  If a rank-k readout cannot represent
  what a full-rank one can, the design is dead and ext_03 is not worth
  running.

  Sanity checks, which validate the algebra rather than the design: at
  k = m a rank-m factorisation can represent ANY m x N matrix, and a
  square +-1 code is invertible, so both k = m rows must reproduce the
  full-rank number.
  The k=m RANK row matches to ~0.0001, which is the algebra being right.
  The k=m FIXED row sits slightly lower, and the reason is worth knowing:
  the ridge penalty is applied to W_g, so a code with a non-unit
  condition number changes the EFFECTIVE regularisation even though the
  code is invertible.  The check is therefore on the right order, not on
  the last digit; at lam -> 0 the two would coincide exactly.

  both difficulties, and a rank-k readout matches the full-rank one well
  below k = m, i.e. the parameter saving costs essentially no accuracy.

  NOT AFFORDABLE for the FROZEN +-1 code.  It loses a large amount of
  accuracy at every k < m, with a spread across codes that is itself as
  large as the effect.  DESIGN section 4.1's realization (b) -- 'no
  combination matrix anywhere' -- is therefore not viable as specified,
  which is a negative result for the stronger of the two claims.
