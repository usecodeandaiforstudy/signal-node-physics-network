  **WHERE 12.33 STOPPED.**  It covered any source that is a FIXED function of the single
  scalar `u`, and said plainly that Yukawa's `exp(-a r)/r` is NOT one -- its SHAPE
  depends on `h` -- and that '`h` would have to index a family of tables'.

  **THE ALGEBRA THAT MAKES THE FAMILY VIABLE.**  With `r = h sqrt(u/k)`,

      z = exp(-a h sqrt(u/k)) / (h sqrt(u/k))     =>     h*z = F(u, beta),  beta = a*h

  so `h*z` depends on `(u, beta)` ALONE, and `beta` is ONE SCALAR.  **The family is
  1-parameter, and its width is a measurement rather than an assumption.**

====================================================================================================
  P3  the recovery: what does it cost, and is it still zero device forwards?
====================================================================================================

  **first, the closed-form operator's answer on a Yukawa response**, so the claim that
  it does not apply is measured here and not inherited:
      closed-form `log_rms` = 4.164e-01   (a Gaussian node reads ~3e-06, 12.33)

  **then the same response, fitted against the TABLE** -- coarse-to-fine over the
  centre, with the width scanned per candidate.  NO DEVICE FORWARDS ARE SPENT: every
  evaluation reads the table, which the calibration already paid for.

                                        value
  --------------------------------------------
  true centre                   [ 0.35 -0.2 ]
  recovered centre           [ 0.3792 -0.2523]
  centre error                      5.986e-02
  true width                           0.8000
  recovered width                      0.5217
  width error                       2.783e-01
  relative MSE of the fit           4.554e-03
  TABLE evaluations used                  960
  DEVICE forwards used                      0

  **THE CENTRE IS RECOVERED AND THE WIDTH IS NOT, and that is a property of the
  kernel rather than of the fit.**  A screened source's response is a short-range bump
  whose radius is set by `1/a`, so scaling `h` and rescaling the amplitude trade off
  against each other and the width is WEAKLY IDENTIFIED; a Gaussian has no such
  degeneracy, which is why the closed form could solve for it.  **This is the price of
  the reach, stated where the number is rather than only in the limits.**

====================================================================================================
  P4  VERDICT
====================================================================================================

  P1: the ONE-parameter family bottoms out at inf and DOES NOT
  improve with more tables -- the core's `r0/h` term is outside `(u, beta)`, so no
  resolution can represent it.  **The TWO-parameter family reaches 3.99e-03**, so physical
  admissibility (a finite core) costs ONE MORE INDEX, and that cost is measured.

  P2: 6 of 6 widths fall inside the family, and the error
  grows only where `beta = a*h` leaves it -- the 0 outside row shows what
  leaving costs, so the family's SCOPE is a stated range rather than a hidden one.

  **P3 IS THE ANSWER TO THE COST QUESTION, AND IT IS AFFIRMATIVE WITH A CAVEAT.**
  The closed-form operator does not apply to Yukawa -- measured here, not assumed --
  and the table-based fit recovers the geometry while spending **ZERO device forwards**.
  **So the project's cost claim survives: it was always 'no device forwards beyond the
  calibration', not 'closed form'.**  The caveat is that the recovery is now a small
  FIT rather than a solve, so it costs table reads and computer time -- neither of which
  is the project's unit of account.

  **AND THE HONEST LIMITS.**  The family covers `beta = a*h` up to a stated maximum, so a
  source whose screening weakens with width leaves it.  The fit is local: it starts from
  a guess and can settle in a wrong basin, which the closed form cannot do -- **that is a
  real loss of guarantee bought with the reach.**  And the family's tables are per
  `beta`, so a device must hold a few tables rather than one.
